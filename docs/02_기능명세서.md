# 02. 기능명세서
## 일본 골프 여행 가이드 웹앱

# 1. 기술 원칙

최우선 순위:

1. 속도
2. 단순함
3. 관리 용이성
4. 정확성
5. 모바일 UX

Google Sheets는 CMS 저장소로 사용한다.

고객 페이지에서 Google Sheets API를 직접 호출하지 않는다.

# 2. 데이터 흐름

```text
Google Sheets
   ↓
서버 데이터 레이어
   ↓
캐시
   ↓
고객 웹앱
```

관리자:

```text
관리자 페이지
   ↓
서버 API
   ↓
Google Sheets 업데이트
   ↓
캐시 무효화
```

# 3. 캐시

권장:

- 고객 조회 캐시: 10~30분
- 관리자 저장 성공 시 관련 캐시 즉시 무효화
- Google API 오류 시 최근 성공 캐시 사용 가능

절대 하지 말 것:

- 고객 브라우저에서 Google Sheets 직접 호출
- 페이지마다 Sheets API 재호출
- 이미지 파일을 Sheet에 직접 저장

# 14. 관리자 기능

## 로그인

초기 MVP:

- 관리자 1개 비밀번호 또는 단일 관리자 인증
- 세션 쿠키
- 관리자 경로 보호

복잡한 권한 시스템 금지.

### 메인 페이지 관리자 진입

메인 페이지(`/`) 오른쪽 상단에 관리자 이모지 버튼(⚙️)이 고정 표시된다.

- `position: fixed; top: 16px; right: 16px; z-index: 1000`
- 배경 이미지와 겹쳐도 식별 가능 (반투명 흰색 배경 + 블러)
- 모바일/태블릿/데스크톱 모두 우측 상단 유지

클릭 시 비밀번호 입력 모달이 열린다:

- Password input + 로그인 버튼 + 취소 버튼
- Enter 키로 로그인 지원
- 비밀번호 검증은 서버 사이드에서만 처리 (`process.env.ADMIN_PASSWORD`)
- 클라이언트 코드에 비밀번호 하드코딩 금지
- `NEXT_PUBLIC_*` 환경변수 사용 금지

올바른 비밀번호 입력 시 기존 세션 생성 후 `/admin/home`으로 이동.

잘못된 비밀번호 입력 시 401 응답 + 모달 내부에 오류 메시지 표시 (페이지 이동 없음).

`/admin` 직접 접근 시 기존처럼 인증 없으면 접근 차단.

## 질문 삭제

관리자가 삭제 버튼 클릭 시:

1. 확인 모달 표시 ("질문을 삭제하시겠습니까? 삭제한 질문은 복구할 수 없습니다.")
2. 취소 → 모달 닫기, 변경 없음
3. 확인 → DELETE `/api/admin/faq` 호출
4. 서버에서 Google Sheet 원본 행을 실제로 삭제 (`deleteDimension`)
5. 성공 시 목록 재-fetch, 실패 시 오류 메시지 표시

`active=FALSE`로 변경하는 숨기기와 달리, 삭제는 원본 시트에서 행 자체를 제거한다.

DELETE API는 관리자 인증 + question ID 존재 여부를 검증한다.

# 22. 인라인 CMS

관리자가 고객 페이지에서 직접 호텔/맛집 데이터를 편집할 수 있다.

적용 대상:

- 호텔 상세 페이지
- 맛집 목록/상세 페이지

동작:

- 관리자 인증 상태에서는 호텔/맛집 카드에 ✏️(수정), 🗑️(삭제) 버튼 표시
- ＋ 버튼으로 새 항목 추가 (목록 상단 또는 하단)
- 수정: 전용 모달(Modal)에서 구조화된 폼 제공
  - HotelEditModal: 기본정보, 체크인/아웃, 조식, 석식, 온천/스파, 기타
  - RestaurantEditModal: 기본정보, 메뉴, 영업정보, 위치/거리, 추가정보, 연결정보
- 삭제: ConfirmModal에서 확인 후 실행 (DELETE API 호출)
- 저장 성공 시 Zustand 캐시 즉시 갱신 (서버 재호출 없음)

관리자 인증 확인:

- `/api/admin/check` — 세션 유효성 검증 (GET, 응답: `{ isAdmin: boolean }`)
- `useAdmin()` 커스텀 훅 — 클라이언트에서 인증 상태 관리

파일 구조:

```text
src/components/inline-cms/
├─ index.ts              # barrel export
├─ EditToolbar.tsx        # ✏️/🗑️/＋ 버튼
├─ ConfirmModal.tsx       # 삭제 확인 모달
├─ HotelEditModal.tsx     # 호텔 수정/추가 모달
└─ RestaurantEditModal.tsx # 맛집 수정/추가 모달

src/hooks/use-admin.ts    # 관리자 인증 훅
```

# 23. Zustand 클라이언트 캐시

지역별 데이터(호텔, 골프장, 맛집)를 클라이언트에서 캐싱한다.

파일: `src/store/guide-store.ts`

캐시 구조:

```text
areaCache: {
  [area: string]: {
    hotels: Hotel[];
    golfCourses: GolfCourse[];
    restaurants: Restaurant[];
    fetchedAt: number;  // 타임스탬프
  }
}
```

TTL: 30분

주요 메서드:

- `getAreaData(area)` — 캐시된 데이터 조회
- `setAreaData(area, data)` — 데이터 저장 + fetchedAt 갱신
- `isCacheValid(area, ttlMs?)` — TTL 유효성 검사
- `invalidateArea(area)` — fetchedAt을 0으로 리셋
- `updateHotel(hotel)` / `addHotel(hotel)` / `deleteHotel(id, area)` — 호텔 캐시 갱신
- `updateRestaurant(restaurant)` / `addRestaurant(restaurant)` / `deleteRestaurant(id, area)` — 맛집 캐시 갱신
- `setAdmin(isAdmin)` — 관리자 인증 상태 저장

용도:

- 인라인 CMS 수정/삭제 후 서버 재호출 없이 즉시 UI 갱신
- 페이지 이동 시 캐시 유효하면 재호출 스킵

# 24. 신규 API 라우트

### `/api/admin/hotel`

|--------|------|----------|

# 28. 반응형 배경 이미지

## 파일 구조

```text
public/background/
├─ main-background-mobile.webp
├─ main-background-tablet.webp
├─ main-background-desktop.webp
├─ sub-background-1-mobile.webp
├─ sub-background-1-tablet.webp
├─ sub-background-1-desktop.webp
├─ sub-background-2-mobile.webp
├─ sub-background-2-tablet.webp
└─ sub-background-2-desktop.webp
```

## 페이지 매핑

| 페이지 | 배경 |
|---|---|
| 메인 (`/`) | main-background-* |
| 도스 (`/dos` + 하위) | sub-background-1-* |
| 벳푸 (`/beppu` + 하위) | sub-background-2-* |

## 반응형 로딩

CSS media query로 화면 크기에 따라 하나의 WebP만 로드한다.

```text
Mobile (기본): 768px 이하 → *-mobile.webp
Tablet (≥768px): 1280px 이하 → *-tablet.webp
Desktop (≥1280px): 1920px 이하 → *-desktop.webp
```

## Overlay

배경 위에 반투명 흰색 overlay를 적용한다.

```css
background: rgba(255, 255, 255, 0.78);
```

목적: 배경은 은은하게, 텍스트 가독성은 높게.

## 구현

- `globals.css`: `.page-bg`, `.bg-main`, `.bg-dos`, `.bg-beppu` 클래스
- `src/app/[area]/layout.tsx`: 지역별 배경 자동 적용
- `src/app/page.tsx`: 메인 페이지 배경 적용

## 원본

PNG 원본은 `background/` 폴더에 보관. 웹에서는 WebP만 사용.
