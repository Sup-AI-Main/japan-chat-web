# 06. DB 스키마 운영 가이드

**Project:** Japan Chat Web  
**Runtime DB:** Supabase PostgreSQL  
**Last production cross-check:** 2026-09-20

For DB changes, cross-check **actual production Supabase → committed migrations → this document**. If they disagree, do not guess.

## Runtime principles
- Supabase/PostgreSQL is the runtime source of truth; Google Sheets is not a runtime datastore.
- Public reads use Data API/server repository paths protected by RLS.
- Admin writes are server-side privileged operations.
- Explicit admin **Delete** means hard DELETE; hide/visibility is separate.
- Missing business facts are never fabricated.

## Current public tables
Production has 17 public tables, all with RLS enabled:

| Group | Tables |
|---|---|
| Core | `areas`, `categories`, `entities` |
| Entity subtype | `golf_courses`, `hotels`, `restaurants` |

## Core identity model
### `areas`
UUID PK; unique `code`; names, icon/description, active/sort, timestamps.

### `categories`
UUID PK; unique `code`; label/icon, `group_type`, allowed entity types, navigation/active/sort metadata.

### `entities`
UUID PK; unique `slug`; `entity_type`, `area_id`, nullable `category_id`, display name, active/sort, timestamps.

`id` is relational identity; `slug` is the URL/business identifier. Do not interchange them.

Production currently contains entity types `GOLF`, `HOTEL`, `PLACE`, and `RESTAURANT`. The old entity-type CHECK constraint is absent. ATTRACTION configuration exists in committed category/field/section migrations, so code must verify intended representation rather than restoring an old CHECK list.

## Subtype tables
`golf_courses.entity_id`, `hotels.entity_id`, and `restaurants.entity_id` are PK+FK one-to-one relations to `entities.id`, with `ON DELETE CASCADE`.

PostgREST can return these embedded one-to-one relations as objects rather than arrays. Do not assume array cardinality from TypeScript casts.

## Relationship/content tables
- `restaurant_locations`: restaurant entity ↔ nearby entity; unique pair; both entity FKs CASCADE.
- `travel_times`: from/to entity FKs both CASCADE; minute/range/display/source/directions/active/sort metadata.
- `faq`: area/category plus optional related entity; scope CHECK is `AREA | SPECIFIC`.
- `content_sections`: parent entity CASCADE; title/content/emoji/sort/visibility.
- `includes_excludes`: parent entity CASCADE; type CHECK `INCLUDED | EXCLUDED`.

### FAQ delete semantics
DB FK `faq.related_entity_id → entities.id` is `ON DELETE SET NULL`. Current application deletion logic removes `SPECIFIC` FAQ for the entity before deleting the entity, while preserving AREA FAQ. Keep this distinction in functional tests.

## Dynamic CMS model
- `entity_categories`: composite PK `(entity_id, category_id)`; both FKs CASCADE.
- `field_definitions`: dynamic field metadata; scope CHECK `ITEM | CATEGORY | AREA | ENTITY_TYPE | GLOBAL`; includes optional entity/area/category/type scope columns and `section_key`.
- `field_definition_scopes`: normalized scopes; CHECK `AREA | CATEGORY | ENTITY_TYPE | ENTITY | GLOBAL`; related FKs CASCADE.
- `entity_field_values`: value_text/value_json, sort/visibility; unique `(entity_id, field_definition_id)`; FKs CASCADE.
- `section_definitions`: section labels/order/visibility; unique `(entity_type, section_key)`.
- `admin_change_logs`: action, entity type/id, before/after JSON, actor metadata, timestamp.

| Source | Target | Delete rule |

Do not change these semantics without checking production rows and product meaning.

## RLS / access model
All 17 public tables currently have RLS enabled and anon SELECT policies. Admin writes use privileged server-side access.

RLS and Data API grants are separate. For new Data API objects, explicitly verify required grants as well as RLS.

## Privileged functions
Production verification:
- `create_entity_with_subtype(...)` — SECURITY DEFINER; `search_path=public, pg_temp`; EXECUTE restricted to postgres/service_role.
- `delete_area_cascade(uuid)`
- `delete_category_cascade(uuid)`
- `delete_entity_cascade(uuid)`
- `delete_field_definition_cascade(uuid)`

The four delete RPCs are SECURITY DEFINER, use the fixed safe search path, and are restricted to postgres/service_role.

`set_updated_at()` is not SECURITY DEFINER and uses the fixed search path.

Do not loosen these grants.

## Attraction note
Committed migrations create the `ATTRACTION` category plus ATTRACTION section/field definitions. Production currently has no existing `ATTRACTION` row among `entities.entity_type` values, and no ATTRACTION subtype table.

Do not restore the old entity-type CHECK or assume a subtype table exists without a separate product/schema decision.

## CRUD verification
For changed CRUD:

```text
CREATE -> DB/read confirmation -> reload
UPDATE -> DB/read confirmation -> reload
DELETE -> reload -> DB SELECT confirms absent
```

For DELETE, repeat the same ID and verify NOT_FOUND/no false success. For entity deletion, separately verify dependent rows and SPECIFIC FAQ cleanup vs AREA FAQ preservation.

## Runtime boundaries
Primary public repository: `src/lib/supabase-cms.ts`. Admin APIs are under `src/app/api/admin/*` and must authenticate before privileged writes.

Do not reintroduce Google Sheets runtime access or dual-read/dual-write fallback.

## Environment safety
Browser-safe Supabase configuration may use `NEXT_PUBLIC_`. Privileged Supabase keys and `ADMIN_PASSWORD` are server-only and must never be committed or printed.

This document contains no secret values.
