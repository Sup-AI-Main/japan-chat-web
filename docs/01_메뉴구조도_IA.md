# 01. 메뉴구조도 IA

## 일본 골프 여행 가이드 웹앱

## 1. 프로젝트 목적

도스·벳푸 골프 여행 고객이 현지에서 스마트폰으로 바로 확인할 수 있는 초경량 여행 가이드 웹앱이다.

이 프로젝트는 기존 NowTravel 예약/결제/회원 시스템과 별개인 독립 웹앱으로 운영한다.

핵심 목표:

- 빠른 로딩
- 모바일 우선
- 관리자 사용 난이도 최소화
- Google Sheets를 콘텐츠 저장소로 활용
- 고객은 Google Sheet를 직접 보지 않음
- 관리자 페이지를 통해 질문/답변을 쉽게 추가·수정
- 불필요한 DB, 회원가입, 복잡한 권한 시스템을 사용하지 않음

---

# 2. 전체 사용자 흐름

```text
/
├─ 도스
│  ├─ 골프장
│  ├─ 호텔
│  └─ 맛집
│
├─ 벳푸
│  ├─ 골프장
│  ├─ 호텔
│  └─ 맛집
│
└─ 공통 안내
   ├─ 온천
   ├─ 차량
   ├─ 환불
   ├─ 환전
   ├─ 추가결제
   └─ 기타
```

도스와 벳푸는 지역별로 다른 데이터를 가진다 (골프장, 호텔, 맛집).

공통 안내는 지역과 무관하게 동일한 내용을 제공한다 (area=ALL).

지역과 카테고리는 `admin_options` Google Sheet 탭에서 동적으로 관리한다. 코드에 하드코딩하지 않는다.

# 3. 고객 웹 경로

## 3.1 메인

`/`

표시:

- 도스
- 벳푸
- 공통 안내 (온천, 차량, 환불, 환전, 추가결제, 기타)

사용자는 지역을 선택하거나 공통 안내에서 카테고리를 직접 선택할 수 있다.

---

## 3.2 지역 홈

`/[area]`

예:

- `/dos`
- `/beppu`

표시 메뉴 (지역별):

1. 골프장
2. 호텔
3. 맛집

공통 안내 카테고리(온천, 차량, 환불, 환전, 추가결제, 기타)는 이 페이지에 표시하지 않는다.

---

## 3.2.1 공통 안내

`/guide`

지역과 무관하게 공통으로 안내하는 내용이다.

표시 카테고리:

1. 온천
2. 차량
3. 환불
4. 환전
5. 추가결제
6. 기타

각 카테고리 클릭 시:

`/guide/[category]`

에서 area=ALL FAQ를 표시한다.

---

## 3.3 골프장

`/[area]/golf`

골프장 목록 표시.

골프장 상세:

`/[area]/golf/[id]`

표시 내용:

- 골프장명
- 일본어명
- 주소
- 전화번호
- Google Maps
- 코스 특징
- 카트
- 캐디
- 클럽하우스 식사
- 욕장/샤워
- 렌탈
- 복장
- 관련 질문
- 해당 골프장과 연결된 맛집

---

## 3.4 호텔

`/[area]/hotel`

호텔 목록.

호텔 상세:

`/[area]/hotel/[id]`

표시:

- 호텔명
- 주소
- 체크인
- 체크아웃
- 조식
- 대욕장/스파
- 식사
- ATM/결제
- 주변 정보
- 해당 호텔 관련 질문
- 해당 호텔 주변 맛집
- 호텔 → 모든 해당지역 골프장 이동시간

---

## 3.5 맛집

`/[area]/restaurant`

필터:

- 전체
- 호텔 근처
- 골프장 근처

상세에서는:

- 이름
- 음식 종류
- 거리/예상시간
- 주소
- 영업시간
- 전화
- 지도
- 관련 질문

---

## 3.6 질문 카테고리

고객에게 보이는 질문 분류:

### 지역별 카테고리 (도스/벳푸 각각)

| 코드       | 표시명 |
| ---------- | ------ |
| GOLF       | 골프장 |
| HOTEL      | 호텔   |
| RESTAURANT | 맛집   |

### 공통 안내 카테고리 (area=ALL)

| 코드          | 표시명   |
| ------------- | -------- |
| ONSEN         | 온천     |
| DRIVER        | 차량     |
| REFUND        | 환불     |
| MONEY         | 환전     |
| EXTRA_PAYMENT | 추가결제 |
| GENERAL       | 기타     |

# 4. 관리자 IA

관리자 페이지:

`/admin`

관리자는 영어 코드나 Google Sheet 구조를 몰라도 사용할 수 있어야 한다.

---

## 4.1 관리자 첫 화면

```text
관리 지역

[ 도스 ]
[ 벳푸 ]
[ 공통 ]
```

지역 선택 후:

도스/벳푸 선택 시:

```text
질문 관리

[ 골프장 ]
[ 호텔 ]
[ 맛집 ]
```

공통 선택 시:

```text
질문 관리

[ 온천 ]
[ 차량 ]

[ 환불 ]
[ 환전 ]

[ 추가결제 ]
[ 기타 ]
```

---

## 4.2 질문 목록

예:

`/admin/questions?area=DOS&category=GOLF`

화면:

```text
도스 > 골프장 질문

[ + 질문 추가 ]

검색 ___________________

반바지 착용 가능한가요?
카오 골프장
[수정] [숨김]

비가 오면 라운딩은 어떻게 되나요?
도스 공통
[수정] [숨김]
```

---

## 4.3 질문 추가/수정

입력 항목:

1. 지역
2. 질문 종류
3. 질문 범위
   - 지역 공통
   - 특정 장소
4. 특정 장소 선택
5. 질문
6. 답변
7. 노출 여부
8. 저장

관리자에게 다음 값은 보여주지 않는다:

- DOS
- BEPPU
- GOLF
- related_id
- internal id
- sort 숫자

이 값은 시스템이 자동 처리한다.

---

# 5. 정렬 UX

Google Sheet 내부에는 `sort` 숫자가 존재한다.

의미:

- 1 = 가장 먼저 표시
- 2 = 두 번째
- 3 = 세 번째

하지만 관리자는 숫자를 직접 입력하지 않는다.

관리자 UI:

- 위로
- 아래로

또는 드래그 앤 드롭.

저장 시 시스템이 자동으로 `1, 2, 3...`을 재정렬한다.

---

# 6. Google Sheets 역할

Google Sheet는 실제 데이터 저장소 역할을 한다.

고객은 Sheet를 직접 보지 않는다.

관리자는 일반적으로 관리자 페이지에서 Q&A를 관리한다.

Sheet는 다음 용도로 사용:

- 원본 데이터 확인
- 골프장 기본정보 수정
- 호텔 기본정보 수정
- 이동시간 수정
- 맛집 데이터 수정
- 관리자 선택 옵션 정의
- FAQ 저장

# 7. Google Sheet 탭

```text
관리안내
golf_courses
hotels
travel_times
restaurants
faq
admin_options
```

## 8.1 admin_options

지역(AREA)과 카테고리(CATEGORY)를 동적으로 관리하는 탭이다.

option_type:

- AREA: 지역 정의 (DOS, BEPPU, ALL 등)
- CATEGORY: 카테고리 정의 (GOLF, HOTEL, ONSEN 등)

group (CATEGORY에만 해당):

- AREA: 지역별 카테고리 (골프장, 호텔, 맛집) → 도스/벳푸 각각 다른 데이터
- COMMON: 공통 안내 카테고리 (온천, 차량, 환불 등) → area=ALL, 지역 무관 동일

관리자 페이지와 고객 페이지 모두 이 탭을 기반으로 UI를 구성한다.

코드에는 카테고리 목록을 하드코딩하지 않는다. group 필드로 지역별/공통을 구분한다.

# 8. 범위 원칙

## 도스

상품 기준:

- 골프장 5개: 카오, 위너스, 포레스트낭칸, 아마카세, 그린랜드
- 호텔 2개: ANA Holiday Inn Tosu, グリーンリッチホテル鳥栖駅前
- 호텔 × 골프장 = 10개 이동 조합
- 호텔 × 골프장 FAQ = 10개 (이동거리/소요시간)

## 벳푸

상품 기준:

- 골프장 4개: 아마카세, 오이타 써니힐, 벳푸 모리, 벳푸클럽
- 호텔 1개: グランドメルキュール別府湾リゾート＆スパ
- 호텔 × 골프장 = 4개 이동 조합
- 호텔 × 골프장 FAQ = 4개 (이동거리/소요시간)

총 14개 이동 조합을 각각 별도 행으로 관리한다.

호텔×골프장 FAQ 질문 형식: `{호텔명}에서 {골프장명}까지 차량으로 얼마나 걸리나요?`
