# 01. 메뉴구조도 IA
## 일본 골프 여행 가이드 웹앱

## 1. 프로젝트 목적

도스·벳푸 골프 여행 고객이 현지에서 스마트폰으로 바로 확인할 수 있는 초경량 여행 가이드 웹앱이다.

이 프로젝트는 기존 NowTravel 예약/결제/회원 시스템과 별개인 독립 웹앱으로 운영한다.

핵심 목표:

- 빠른 로딩
- 모바일 우선
- 관리자 사용 난이도 최소화
- Google Sheets를 콘텐츠 저장소로 활용
- 고객은 Google Sheet를 직접 보지 않음
- 관리자 페이지를 통해 질문/답변을 쉽게 추가·수정
- 불필요한 DB, 회원가입, 복잡한 권한 시스템을 사용하지 않음

---

# 2. 전체 사용자 흐름

```text
/
└─ 지역 선택
   ├─ 도스
   │  ├─ 골프장
   │  ├─ 호텔
   │  ├─ 맛집
   │  ├─ 온천
   │  ├─ 차량
   │  ├─ 환불
   │  ├─ 환전
   │  ├─ 추가결제
   │  └─ 기타
   │
   └─ 벳푸
      ├─ 골프장
      ├─ 호텔
      ├─ 맛집
      ├─ 온천
      ├─ 차량
      ├─ 환불
      ├─ 환전
      ├─ 추가결제
      └─ 기타
```

도스와 벳푸는 동일한 UI를 사용하고 데이터만 `area` 기준으로 필터링한다.

지역과 카테고리는 `admin_options` Google Sheet 탭에서 동적으로 관리한다. 코드에 하드코딩하지 않는다.

# 3. 고객 웹 경로

## 3.1 메인

`/`

표시:

- 도스
- 벳푸

사용자는 한 번의 선택으로 지역을 진입한다.

---

## 3.2 지역 홈

`/[area]`

예:

- `/dos`
- `/beppu`

표시 메뉴:

1. 골프장
2. 호텔
3. 맛집
4. 온천
5. 차량
6. 환불
7. 환전
8. 추가결제
9. 기타

---

## 3.3 골프장

`/[area]/golf`

골프장 목록 표시.

골프장 상세:

`/[area]/golf/[id]`

표시 내용:

- 골프장명
- 일본어명
- 주소
- 전화번호
- Google Maps
- 코스 특징
- 카트
- 캐디
- 클럽하우스 식사
- 욕장/샤워
- 렌탈
- 복장
- 관련 질문
- 해당 골프장과 연결된 맛집

---

## 3.4 호텔

`/[area]/hotel`

호텔 목록.

호텔 상세:

`/[area]/hotel/[id]`

표시:

- 호텔명
- 주소
- 체크인
- 체크아웃
- 조식
- 대욕장/스파
- 식사
- ATM/결제
- 주변 정보
- 해당 호텔 관련 질문
- 해당 호텔 주변 맛집
- 호텔 → 모든 해당지역 골프장 이동시간

---

## 3.5 맛집

`/[area]/restaurant`

필터:

- 전체
- 호텔 근처
- 골프장 근처

상세에서는:

- 이름
- 음식 종류
- 거리/예상시간
- 주소
- 영업시간
- 전화
- 지도
- 관련 질문

# 4. 관리자 IA

관리자 페이지:

`/admin`

관리자는 영어 코드나 Google Sheet 구조를 몰라도 사용할 수 있어야 한다.

---

## 4.1 관리자 첫 화면

```text
관리 지역

[ 도스 ]
[ 벳푸 ]
[ 공통 ]
```

지역 선택 후:

```text
질문 관리

[ 골프장 ]
[ 호텔 ]
[ 온천 ]

[ 차량 ]
[ 맛집 ]
[ 기타 ]

[ 환불 ]
[ 환전 ]
[ 추가결제 ]
```

---

## 4.2 질문 목록

예:

`/admin/questions?area=DOS&category=GOLF`

화면:

```text
도스 > 골프장 질문

[ + 질문 추가 ]

검색 ___________________

반바지 착용 가능한가요?
카오 골프장
[수정] [숨김]

비가 오면 라운딩은 어떻게 되나요?
도스 공통
[수정] [숨김]
```

---

## 4.3 질문 추가/수정

입력 항목:

1. 지역
2. 질문 종류
3. 질문 범위
   - 지역 공통
   - 특정 장소
4. 특정 장소 선택
5. 질문
6. 답변
7. 노출 여부
8. 저장

관리자에게 다음 값은 보여주지 않는다:

- DOS
- BEPPU
- GOLF
- related_id
- internal id
- sort 숫자

이 값은 시스템이 자동 처리한다.

---

# 5. 정렬 UX

Google Sheet 내부에는 `sort` 숫자가 존재한다.

의미:

- 1 = 가장 먼저 표시
- 2 = 두 번째
- 3 = 세 번째

하지만 관리자는 숫자를 직접 입력하지 않는다.

관리자 UI:

- 위로
- 아래로

또는 드래그 앤 드롭.

저장 시 시스템이 자동으로 `1, 2, 3...`을 재정렬한다.

---

# 6. Google Sheets 역할

Google Sheet는 실제 데이터 저장소 역할을 한다.

고객은 Sheet를 직접 보지 않는다.

관리자는 일반적으로 관리자 페이지에서 Q&A를 관리한다.

Sheet는 다음 용도로 사용:

- 원본 데이터 확인
- 골프장 기본정보 수정
- 호텔 기본정보 수정
- 이동시간 수정
- 맛집 데이터 수정
- 관리자 선택 옵션 정의
- FAQ 저장

# 7. Google Sheet 탭

```text
관리안내
golf_courses
hotels
travel_times
restaurants
faq
admin_options
```

## 8.1 admin_options

지역(AREA)과 카테고리(CATEGORY)를 동적으로 관리하는 탭이다.

option_type:

- AREA: 지역 정의 (DOS, BEPPU, ALL 등)
- CATEGORY: 카테고리 정의 (GOLF, HOTEL, ONSEN 등)

관리자 페이지와 고객 페이지 모두 이 탭을 기반으로 UI를 구성한다.

# 8. 범위 원칙

## 도스

상품 기준:

- 골프장 5개
- 호텔 2개
- 호텔 × 골프장 = 10개 이동 조합

## 벳푸

상품 기준:

- 골프장 4개
- 호텔 1개
- 호텔 × 골프장 = 4개 이동 조합

총 14개 이동 조합을 각각 별도 행으로 관리한다.
